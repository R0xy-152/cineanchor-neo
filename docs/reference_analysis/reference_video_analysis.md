## Human-reviewed synthesis

### Dataset quality and contamination

- 13/13 files are HEVC platform screen recordings at 592×1280 (near 9:16), about 30 fps, with mono AAC audio. Duration range is 16.97–28.47 seconds; mean is 21.31 seconds.
- 13/13 contain persistent platform pollution: iPhone status / Dynamic Island at top, Reels navigation, right-side like/comment/share/save controls, account and caption area, and bottom comment box. Several also contain notification banners.
- These controls overlap the intended video, so a rectangular crop cannot remove all pollution without cutting real content. The correct analysis policy is semantic exclusion; use `--crop` / `--crop-config` only when the source has removable outer bars.
- Dominant-color results include platform black/white UI pixels because no crop was applied. They are useful for broad palette direction, not exact brand-color extraction.
- Automatic scene detection averages 6.5 candidates per file but is intentionally non-semantic. White flashes and fast gameplay create false positives; `f560...` produces 27 candidates for this reason.

### What is reusable

The stable grammar is: information hook (date/name) → emotional close-up and title → full-height poster → optional interaction/dialogue → bright transition → white brand card. Reusable units are fixed image slots, typography presets, theme colors, subtitle safe zones, deterministic particles and end-card layout. Character animation and game scenes are inputs, not something the template must synthesize.

### Default reusable timeline

| Time | Component | Source type | Implementation |
|---:|---|---|---|
| 0.0–2.0s | Birthday Date Card | operator packaging | deterministic 2D text / shape layers |
| 2.0–3.0s | Character Name Card | operator packaging | serif/bold text, white flash |
| 3.0–5.5s | Theme Ribbon + close-up | packaging + user PNG | scale / crop keyframes, ribbon title |
| 5.5–9.0s | Character Poster Stage | operator packaging | full PNG, background type, support cards |
| 9.0–12.5s | Interaction / Dialogue | optional gameplay or user images | V0.2 falls back to the main PNG; subtitle overlay |
| 12.5–15.0s | Brand End Card | operator packaging | cloud wipe, white card, Logo, CTA |

For a 27s export, extend the interaction segment to about 12.0–23.5s and end card to 23.5–27.0s. Use 27s only when gameplay or enough supplementary images exist.

### Transition decision

Implement now: hard cut, fade, short blur zoom, white flash, deterministic petals/particles, programmatic cloud wipe and white Logo-card transition. Delay optical flow, complex motion blur, fluid smoke, beat-sync, alpha transition libraries and any generated-video bridge. The first group is stable and testable with Pillow/Canvas/Blender layers plus FFmpeg; the second group adds asset, performance or QA risk without improving the template's core value.

### Text and palette findings

- Main titles are composition elements: large all-caps words on ribbons, blocks or high-contrast whitespace. They are not ordinary subtitles.
- Character names use oversized serif or bold display type and frequently sit behind or beside the character.
- Dates are usually the opening's largest information, formatted as `MM.DD`, `MM/DD` or stacked digits.
- Dialogue stays bottom-centered, white with thick black outline, and within two lines.
- End cards consistently prefer white / very light backgrounds, a centered Logo and circular character image.
- Palettes are character-specific but commonly combine white with one saturated primary and a cool secondary. The template therefore exposes two colors rather than fixed IP colors.

### Tool usage

```powershell
$videos = (Get-ChildItem E:\cineanchor\bluearchive\*.mp4).FullName
python tools\analyze_reference_videos.py @videos `
  --output-dir docs\reference_analysis `
  --ffmpeg C:\path\to\ffmpeg.exe `
  --ffprobe C:\path\to\ffprobe.exe
```

Apply one crop to all inputs with `--crop W:H:X:Y`, or pass `--crop-config crop.json`. The JSON is a basename/path to crop mapping, for example:

```json
{
  "screen_recording_a.mp4": "540:1080:0:100",
  "E:\\references\\screen_recording_b.mp4": "540:1080:20:80"
}
```

Crop is applied before 1 fps extraction, scene detection and color analysis. It is not an inpainting tool and cannot remove controls overlaid inside the retained rectangle.

## Interpretation guardrails

- Apply crop configuration before reading scene cuts, colors or contact sheets when the source is a platform screen recording.
- Treat status bars, Reels/TikTok controls, like/comment/share buttons, handles, notifications and letterboxing outside the crop as contamination.
- Scene detection is a visual-difference heuristic. White flashes, particles and UI popups can create false positives.
- Contact sheets are evidence for manual analysis; they are not semantic classifications.
